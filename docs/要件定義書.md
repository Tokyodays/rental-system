## 1. システム概要

### 1.1 システム名
**Rental System**

### 1.2 概要
車両（自動車、バイク、自転車など）のレンタル管理を行うマルチテナント SaaS アプリケーション。複数の店舗が独立して車両の貸出・返却・顧客管理を行うことができるシステム。

### 1.3 主な特徴
- **マルチテナント対応**: 複数の店舗を独立して管理
- **多言語・多通貨対応**: 地域に応じた言語と通貨に対応
- **スタッフ・ロール管理**: 店舗管理者と一般スタッフの権限分離
- **QR コード連携**: 車両の QR コードスキャンによる識別
- **取引履歴管理**: 全ての貸出・返却の履歴を追跡
- **顧客管理**: 顧客情報の一元管理（パスポート番号、免許番号など）

## 2. ビジネス要件

### 2.1 対象ユーザー
- **店舗管理者（Admin）**: 店舗の運営管理、スタッフ管理、設定変更
- **店舗スタッフ（Staff）**: 日常の貸出・返却業務、顧客管理
- **システム管理者（System Admin）**: マルチテナント環境全体の管理

### 2.2 主要ビジネスプロセス

#### 2.2.1 車両管理プロセス
1. 新規車両の登録
2. 車両情報の編集・更新
3. 車両の写真管理（複数枚対応）
4. 車両ステータスの管理（利用可能、貸出中、予約中、メンテナンス中）

#### 2.2.2 貸出・返却プロセス
1. 顧客選択（既存顧客から検索、または新規作成）
2. 車両選択（QR コードスキャンまたは手動検索）
3. 返却日時の設定
4. 貸出価格の入力
5. 貸出確認・登録
6. 返却時の車両状態確認と返却登録

#### 2.2.3 顧客管理プロセス
1. 顧客情報の登録（氏名、パスポート番号、免許番号）
2. 顧客情報の編集・更新
3. 顧客ステータスの管理（アクティブ、非アクティブ）
4. 顧客削除

#### 2.2.4 スタッフ管理プロセス（管理者のみ）
1. スタッフアカウントの作成
2. スタッフのロール割り当て（管理者、スタッフ）
3. スタッフアカウントの削除

### 2.3 管理画面
- **ダッシュボード**: リアルタイム統計情報（貸出中台数、利用可能台数、本日の取引数）
- **取引履歴**: 全ての貸出・返却の履歴とフィルタリング機能
- **レポート**: エクスポート機能（CSV、PDF など）

## 5. 認証・ユーザー管理の現状と潜在的な問題

### 5.1 現在のアーキテクチャ

```
┌─────────────────────────────────────────────────────────┐
│  Nuxt Client (Vue 3)                                    │
│  ├─ login.vue: ユーザー名/パスワード入力               │
│  ├─ useStaff.ts: スタッフ情報取得・キャッシュ         │
│  └─ auth.global.ts: ルート保護（認証チェック）        │
└──────────────────┬──────────────────────────────────────┘
                   │
                   ↓
┌─────────────────────────────────────────────────────────┐
│  Nuxt Server API                                        │
│  ├─ /api/admin/users.post.ts: ユーザー作成            │
│  └─ /api/admin/users.delete.ts: ユーザー削除          │
└──────────────────┬──────────────────────────────────────┘
                   │
                   ↓
┌─────────────────────────────────────────────────────────┐
│  Supabase                                               │
│  ├─ auth.users (PostgreSQL トリガー連携)             │
│  ├─ public.staff (スタッフ情報テーブル)               │
│  └─ RLS ポリシー (店舗ごと分離)                       │
└─────────────────────────────────────────────────────────┘
```

### 5.2 潜在的な問題

#### 問題 1: Auth と Staff テーブルの同期不全
**症状**:
- スタッフアカウント新規作成後、staff テーブルにレコードが存在しない
- ログイン時に `staff.store_id === null` となるケースがある
- `fetchStaff()` でデータが取得できず、デフォルト値が使用される

**原因**:
1. users.post.ts で staff レコード作成前に auth.users を作成している
2. Supabase のトリガー関数 `handle_new_user()` が確実に実行されない可能性
3. auth.users 作成と staff レコード挿入の間のタイミング問題

**影響**:
- ユーザーが店舗情報にアクセスできない
- ロール情報が不正な状態になる
- ダッシュボード統計情報が表示されない

#### 問題 2: ユーザー削除時の不整合
**症状**:
- auth.users は削除されるが、staff レコードが残る可能性
- 孤立した staff レコードが発生

**原因**:
- auth.users 削除のみで、public.staff 削除を明示的に行っていない
- カスケード削除の信頼性が不明

**影響**:
- データベースに不要なレコードが蓄積
- RLS ポリシー評価時にパフォーマンス低下

#### 問題 3: useStaff の不安定性
**症状**:
- `staff.value === null` のまま処理が進む
- コンポーネントのマウント時にラッシュ状態になる可能性

**原因**:
1. `useSupabaseUser()` が不安定（コメントで言及）
2. `onMounted()` と `auth.onAuthStateChange()` の両方で `syncUser()` を呼び出し
3. キャッシング戦略が不十分（`staff.value.id === uid` チェックでは不十分）

**影響**:
- 画面がちらつく（loading 状態が頻繁に変わる）
- 複数の API 呼び出し

#### 問題 4: ユーザー名とメールの内部マッピング
**症状**:
- ユーザー名を `username@rental.local` に変換している
- 外部システム連携が困難

**原因**:
- Supabase の auth.users には通常メールアドレスが必須
- ユーザー名ベースのログインとの整合性

**影響**:
- ユーザー名とメールの対応関係が複雑
- デバッグが困難

## 6. 推奨される改善策

### 6.1 スタッフアカウント新規作成の安定化
```
改善前: API リクエスト → Auth 作成 → Staff 更新（トリガー頼み）
改善後: API リクエスト → Staff 作成 → Auth 作成 → 確認チェック
```

### 6.2 明示的な削除処理
- `users.delete.ts` で auth.users と staff レコードの両方を削除
- トランザクション的な処理を検討

### 6.3 useStaff の安定化
- 初期化フロー（onMounted vs auth.onAuthStateChange）を統一
- キャッシング戦略の見直し
- エラー時のリトライロジック

### 6.4 ユーザー認証エラーの詳細化
- エラータイプの区分（認証失敗 vs ネットワークエラー vs 権限不足）
- ユーザーへの明確なメッセージング

## 8. データモデル概要

### 8.1 主要テーブル

| テーブル | 説明 |
|---------|------|
| `auth.users` | Supabase 認証ユーザー |
| `public.stores` | テナント（店舗） |
| `public.staff` | スタッフ（ユーザー情報） |
| `public.staff_roles` | スタッフロール定義 |
| `public.vehicles` | 車両マスタ |
| `public.vehicle_categories` | 車両カテゴリ |
| `public.vehicle_statuses` | 車両ステータス |
| `public.vehicle_photos` | 車両写真 |
| `public.customers` | 顧客情報 |
| `public.customer_statuses` | 顧客ステータス |
| `public.transactions` | 貸出・返却取引 |
| `public.currency` | 通貨マスタ |

### 8.2 主要なリレーション

```
stores
  ├─ staff (1 : N) ... スタッフ
  ├─ vehicles (1 : N) ... 車両
  ├─ customers (1 : N) ... 顧客
  ├─ transactions (1 : N) ... 取引
  └─ currency (M : 1) ... 通貨

staff
  ├─ user (1 : 1) via auth.users
  ├─ store (M : 1) ... 所属店舗
  └─ role (M : 1) ... スタッフロール

vehicles
  ├─ category (M : 1) ... 車両カテゴリ
  ├─ status (M : 1) ... ステータス
  ├─ photos (1 : N) ... 写真
  └─ transactions (1 : N) ... 取引

customers
  ├─ store (M : 1) ... 所属店舗
  ├─ status (M : 1) ... ステータス
  └─ transactions (1 : N) ... 取引

transactions
  ├─ vehicle (M : 1) ... 車両
  ├─ customer (M : 1) ... 顧客
  └─ store (M : 1) ... 店舗
```
