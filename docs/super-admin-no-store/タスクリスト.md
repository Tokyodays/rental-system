# super_admin を店舗に紐づけない 実装タスクリスト

## 背景・方針

- super_admin はオーナー本人であり、店舗を持たない。
- 現状は DB の `staff.store_id NOT NULL` 制約のせいで、super_admin にも店舗が必要になっている。
- 本番(`dyrhkvdmzcvslgbqofgh`)には auth ユーザーが 0 件で、`admin` が存在しない。店舗・サンプルデータは投入しない。
- アプリ側(useStaff / middleware / requireStaffRole / RLS)は store_id が null の super_admin をほぼ想定済み。変更の中心は DB。
- 各タスクは完了ごとにコミットし、確認項目を満たしてから次へ進む。dev → 本番の順で適用する。

## Phase 1: DB(dev で検証)

- [ ] T1 マイグレーション作成 `supabase/migrations/20261010000000_allow_null_store_for_super_admin.sql`
  - `staff.store_id` の NOT NULL を外す
  - CHECK 制約: `store_id IS NOT NULL OR role_id = super_admin`
  - `handle_new_user` から `EXCEPTION WHEN not_null_violation` を外す
  - `Users can update their own profile` の WITH CHECK を `IS NOT DISTINCT FROM` に変更
- [ ] T2 dev に `--dry-run` → 適用。制約・ポリシー・関数を読み取りで確認
- [ ] T3 dev の `admin` の store_id を null にする(`seed.sql` 更新 + dev DB へ反映)

**確認**: dev の admin が store_id=null で `/admin/login` → `/admin/stores` に入れる。branchadmin 等の既存ユーザーは影響なし。

## Phase 2: アプリ

- [ ] T4 `server/api/admin/users.post.ts`: super_admin 以外のロールでは store_id 必須(400)
- [ ] T5 `app/types/database.types.ts`: `staff.store_id` を `string | null` に更新(型再生成 or 手修正)

**確認**: `nuxt typecheck` / lint が通る。

## Phase 3: テスト

- [ ] T6 E2E: super_admin が店舗なしで管理画面に入れること、店舗なしの admin/staff が作れないこと(CHECK/API)を追加
- [ ] T7 E2E 全体を実行しグリーンを確認(既存 36 テスト + 追加分)

## Phase 4: 本番

- [ ] T8 本番に `--dry-run` → マイグレーション適用 → CLI リンクを dev に戻す
- [ ] T9 本番に `admin` を作成(強いパスワード、store_id=null、role=super_admin)。パスワードはリポジトリ・メモリに保存しない
- [ ] T10 本番で `/admin/login` にログインできることを確認。店舗 0 件・サンプルデータなしのままであること

## 範囲外(確認済みで変更不要)

useStaff / auth.global / requireStaffRole / stores.post / 業務テーブルの RLS(`store_id = get_auth_store_id()`)/ `sync_user_store_map` / Storage ポリシー。
