# 課金システム 要件定義書

作成日: 2026-07-13
対象: rental-system(マルチテナント車両レンタルSaaS / Nuxt 4 + Supabase)

## 1. 背景・目的

現在、店舗(store)のadminユーザーは無償でスタッフインターフェースを利用できる。
本機能では、店舗単位の月額サブスクリプション課金を導入し、Stripeを通じて自動的に料金を回収する。

## 2. 課金モデル(ヒアリング確定事項)

| 項目 | 決定内容 |
|------|---------|
| 課金単位 | **店舗(store)単位**。1店舗 = 1サブスクリプション。店舗のadminが支払いを行う |
| 料金体系 | **月額固定・全体で1つの料金**。super_adminが金額を設定する |
| 決済手段 | **Stripe**(サブスクリプション / クレジットカード) |
| 課金サイクル | **利用開始日アンカー方式**。利用開始日から翌月同日までが1ヶ月。超過すると次月分の課金が発生 |
| 無料トライアル | **あり(期間固定)**。トライアル終了日が課金開始日となり、以後そこを起点に毎月同日更新 |
| 未払い時 | **猶予期間後に利用停止**。Stripeの自動リトライ期間中は利用可。リトライ失敗確定後にスタッフ画面の利用を制限 |

## 3. 機能要件

### 3.1 super_admin(管理コンソール)

- **FR-01** 月額料金(金額・通貨)を設定・変更できる。
  - 変更は新規契約に即時適用。既存契約には**次回更新時から**適用する(日割り・遡及請求は行わない)。
- **FR-02** トライアル日数を設定できる(デフォルト14日。0日=トライアルなしも設定可)。
- **FR-03** 全店舗の課金ステータス一覧を確認できる(未契約 / トライアル中 / 有効 / 支払い遅延 / 停止 / 解約)。
- **FR-04** 特定店舗の課金を手動で免除できる(社内利用・特約店舗向けの `exempt` フラグ)。

### 3.2 admin(スタッフインターフェース)

- **FR-05** 設定画面から契約手続き(Stripe Checkoutへのリダイレクト)を行える。契約前に月額料金とトライアル期間が明示される。
- **FR-06** 契約状況(ステータス、次回請求日、金額)を確認できる。
- **FR-07** Stripe Billing Portal経由で、カード情報の変更・請求履歴の確認・解約ができる。
- **FR-08** 解約は**期間末解約**とする。解約後も現在の請求期間終了日までは利用可能。
- **FR-09** 支払い失敗時、admin本人は課金ページにアクセスして支払い方法を修正できる(復旧導線を塞がない)。

### 3.3 staff

- **FR-10** staffは課金操作を行えない。店舗が利用停止状態の場合、staffはスタッフ画面を利用できず、「管理者に連絡してください」という案内画面を表示する。

### 3.4 システム(アクセス制御)

- **FR-11** 店舗の課金ステータスに応じてスタッフインターフェースへのアクセスを制御する:

| ステータス | アクセス可否 |
|-----------|-------------|
| 未契約 | 不可(adminは契約ページのみ可) |
| トライアル中 (`trialing`) | 可 |
| 有効 (`active`) | 可 |
| 支払い遅延・猶予中 (`past_due`) | 可(画面上部に警告バナー表示) |
| 停止 (`unpaid`) | 不可(adminは課金ページのみ可) |
| 解約済み・期間内 (`active` + 期間末解約予約) | 可 |
| 解約済み・期間終了 (`canceled`) | 不可(adminは再契約ページのみ可) |
| 免除 (`exempt`) | 可 |

- **FR-12** super_adminと管理コンソールは課金ステータスの影響を受けない。
- **FR-13** 課金ステータスはStripe Webhookで同期し、DBを単一の参照元とする(画面表示・アクセス制御はDBのみ参照)。

## 4. 課金サイクルの詳細仕様

- 課金起点日 = トライアル終了日(トライアル0日の場合は契約日)。
- 毎月の更新日は起点日と同日(アニバーサリー課金)。**Stripeのサブスクリプション標準動作**(subscription作成日 = billing cycle anchor)をそのまま利用する。
- 月末エッジケース: 1/31開始の場合、2月は末日(2/28 or 2/29)に請求される(Stripe標準挙動)。3月以降は31日に戻る。
- 期間を超過した時点でStripeが自動的に次月分の請求を発行する(= 「超えると次の月の利用開始」)。

## 5. 非機能要件

- **NFR-01** Webhookは署名検証(`stripe-signature`)を必須とし、冪等に処理する(同一イベントの重複配信に耐える)。
- **NFR-02** カード情報は自システムで一切保持しない(PCI DSS対応はStripe Checkout / Billing Portalに委譲)。
- **NFR-03** StripeのSecret Key・Webhook Secretはサーバー環境変数でのみ扱い、クライアントに露出しない。
- **NFR-04** Webhook欠落に備え、Stripe APIから状態を再同期できる手段(手動同期エンドポイント)を用意する。
- **NFR-05** 課金関連テーブルはRLSで保護する(書き込みはservice roleのみ、参照は自店舗のみ)。

## 6. スコープ外(本フェーズでは実装しない)

- 複数プラン(Basic/Pro等)・従量課金・年額プラン
- 請求書払い(銀行振込)・コンビニ払い等のカード以外の決済手段
- 領収書・請求書のカスタムPDF生成(Stripe標準のインボイスメールで代替)
- クーポン・割引コード
- 店舗ごとの個別料金設定
- 税(Stripe Taxによる自動計算)— 将来対応。当面は税込価格として金額を設定する

## 7. 前提・依存

- Stripeアカウント(本番・テスト)が用意されていること。
- 環境変数: `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` を Vercel(本番)およびローカル `.env` に設定。
- 通貨はStripeがサポートする通貨から選択(既存の `currency` テーブルの通貨はすべてStripe対応)。1つのサブスクリプション料金は単一通貨とする。
