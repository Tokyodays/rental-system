# 課金システム 実装タスクリスト

フェーズ順に実装する。各フェーズ末尾の確認項目を満たしてから次へ進む。

- [ ] T0-1 Stripeアカウント(テストモード)の用意、APIキー取得

- [ ] T0-3 `.env.example` に `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` を追記、ローカル `.env` 設定
- [ ] T0-4 Stripe CLI(`stripe listen`)でのローカルWebhook転送手順を README または docs に記載

## Phase 1: DBスキーマ

- [ ] T1-1 マイグレーション作成: `billing_settings` / `subscriptions` / `billing_webhook_events`(設計書 §2)
- [ ] T1-2 RLSポリシー(SELECTのみ許可、書き込みはservice role限定)
- [ ] T1-3 seed: `billing_settings` 初期行(料金は仮値)、E2Eシード店舗の `subscriptions.status = 'exempt'`

**確認**: 既存E2E 36テストがグリーンのまま(この時点ではアクセス制御未実装なので当然通る)

## Phase 2: Stripe連携サーバーAPI

- [ ] T2-1 Stripeクライアントのserver utility(`server/utils/stripe.ts`)
- [ ] T2-2 `PUT /api/admin/billing/settings`: 料金・トライアル日数更新。初回はProduct作成、変更時は新Price作成+旧Price archive+既存契約のPrice差し替え(`proration_behavior: 'none'`)
- [ ] T2-3 `GET /api/admin/billing/settings`
- [ ] T2-4 `POST /api/billing/checkout`: Checkout Session作成(mode=subscription, trial_period_days, Customer metadata に store_id)
- [ ] T2-5 `POST /api/billing/portal`: Billing Portal Session作成(期間末解約のみ許可するPortal Configuration)
- [ ] T2-6 `POST /api/billing/webhook`: 生ボディ署名検証、`billing_webhook_events` による冪等化、5イベントの同期処理(設計書 §4)
- [ ] T2-7 `GET /api/billing/subscription`(自店舗の状態返却)
- [ ] T2-8 `GET /api/admin/billing/subscriptions` / `POST /api/admin/billing/exempt` / `POST /api/admin/billing/sync`
- [ ] T2-9 Webhookハンドラのユニットテスト(vitest + イベントfixture、冪等性含む)

**確認**: Stripeテストモードで Checkout → Webhook → `subscriptions` 行が `trialing` になる一連の流れが通る
